## For visitors

The home page opens with a dashboard to take in at a glance: seven cells, each opening a panel in place. Below
it the Chosen work honeycomb, eight projects that each open a short popup. The career is the Career cell. Four pages go further: `/projects/`
shows every project in one honeycomb with field and type-of-work filters, `/research/` holds the full
publication list with the numbers derived from it, `/lab/` has the three demos, and `/contact/` is where
to write (the Hi cell and the menu's Contact open it). A project has no page of its own: its popup is its whole
description. The CV is one download from any page.

## For the maintainer

Everything the site says is a file under `website/src/`: one Markdown file per project (frontmatter only), JSON
for the profile, career, skills and education, and a CSV of publications. The
content collections in `content.config.ts` validate the project, career, collaboration and publication files,
so a broken field stops the build instead of shipping an empty block. A pull request is checked and built
before it can merge; merging into `main` publishes. The CV and the plain-text profile in `files/` mirror the
site data by hand.
